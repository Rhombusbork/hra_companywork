# PPT 작업 지침 (Claude Code 웹에서 이어 하기)

12/12 기업실무 발표 PPT 를 웹 Claude Code 세션에서 이어 만들기 위한 지침이다. 2026-11-27 로컬 세션이 썼다.
**첫 일은 템플릿 찾기다.** 넓게, 많이, 직접 열어 보고 찾는다.

## 0. 시작할 때

1. `git pull` 한다. 웹 세션이 `claude/…` 브랜치에서 시작했어도 끝날 때 `main` 에 합친다 (저장소 CLAUDE.md).
2. 다음 순서로 읽는다.
   - [../CLAUDE.md](../CLAUDE.md): 저장소 규칙. **이 저장소는 공개다.**
   - [../사람의_PPT_특징.md](../사람의_PPT_특징.md): PPT 원칙. 모든 판단의 기준이다.
   - [PPT_제작계획.md](PPT_제작계획.md): 지난 발표 과정, 컷 초안, 디자인 후보 첫 목록, 일정
   - [참고/린스타트업_PPT_제작계획.md](참고/린스타트업_PPT_제작계획.md): 지난번 계획이 실제로 어떻게 생겼는지 본보기. 안의 링크(대본 등)는 로컬에만 있어서 열리지 않는다
   - [참고/효과적인_발표_이론.md](참고/효과적인_발표_이론.md)
   - 내용: [../제주_웹서비스_MVP/18_기업실무_텍스트_초안.md](../제주_웹서비스_MVP/18_기업실무_텍스트_초안.md), [09](../제주_웹서비스_MVP/09_서비스_요약.md), [14](../제주_웹서비스_MVP/14_서비스_기획서.md)
3. 단계 하나가 끝날 때마다 커밋하고 `main` 에 push 한다. 큰 결정은 [06_이어하기.md](../제주_웹서비스_MVP/06_이어하기.md) 에 날짜와 한 줄.

## 1. 지켜야 할 것

- **공개 저장소**: 실명·학번·연락처, 에타 닉네임은 올리지 않는다. 발표자 이름이 든 .pptx 는 커밋하지 않는다.
- **템플릿 파일과 미리보기 그림은 커밋하지 않는다.** 저작권이 있고, Slidesgo 는 템플릿 파일을 다시 배포하는 것을 막는다. 링크와 설명만 적는다. 받은 파일은 `ppt/templates/` 에 두는데, 이 폴더는 git 에서 뺐다.
- **[확인]과 [추측]을 나눠 적는다** (저장소 규칙). 페이지를 직접 열어 본 것만 [확인]이다. 검색 결과 요약만 보고 적은 것은 [추측]이다.
- 사용자 말을 거의 그대로 쓰고, 계획이나 예시를 마음대로 더하지 않는다. 더할 것은 [제안]으로 적는다.
- 글은 [../사람의_글_특징.md](../사람의_글_특징.md) 를 따른다.
- 형식은 `.pptx` 다 (사용자 결정).

## 2. 1단계: 템플릿 찾기 (가장 먼저, 가장 열심히)

### 목표

- 후보를 **30개 이상 훑어보고**, 그중 **20개 이상을 표에 적고**, **5개를 추려** 사용자에게 고르게 한다.
- 결과는 새 파일 `ppt/템플릿_후보.md` 에 쓴다. [PPT_제작계획.md](PPT_제작계획.md) 3절의 첫 목록(14개)도 다시 열어 확인하고 표에 합친다.

### 무엇을 찾나

이번 발표에 맞는 템플릿의 조건이다 (원칙 파일과 [PPT_제작계획.md](PPT_제작계획.md) 2절 컷 초안에서 나옴).

| 조건 | 왜 | 확인하는 법 |
|---|---|---|
| 사진·일러스트가 적고 빈 공간이 많다 | 스톡 사진을 쓰지 않는다. 본문 30% 이상을 비운다 | 미리보기 장을 모두 넘겨 본다 |
| 색이 적다. 파랑 계열이거나 색을 바꾸기 쉽다 | 사이트 색(남색 `#042880`, 파랑 `#0e6fc1`, 하늘 `#049edc`, 귤색 `#f2711c` 강조)과 맞춘다 | 장식이 그림(PNG)이면 색을 못 바꾼다. 도형이면 바꿀 수 있다 |
| 휴대폰 틀(목업) 장이 있다 | 사이트 화면 캡처를 많이 넣는다 | 목업 장이 있는지, 화면 자리가 바꿔 넣을 수 있는 칸인지 |
| 큰 글자 한 장 | 키워드 60pt 장 | 제목만 크게 있는 장 |
| 둘을 비교하는 장 | 5컷(관광 → 제주대), 13컷(고치기 전 → 뒤) | 좌우 두 칸 |
| 단계 화살표 장 | 9컷(게시판 → Actions → JSON → Pages → 휴대폰) | 가로 4~5단계 |
| 큰 숫자 장 | 8·10컷(D-1, 하루 4번) | 숫자 하나를 크게 |
| 칸(벤토·그리드) 구성 | 사이트 홈이 칸 구성이라 이어진다 (있으면 좋음) | 여러 칸 장 |
| .pptx 로 받을 수 있다 | 만들기 스크립트가 pptx XML 을 고친다 | PowerPoint 다운로드가 있는지. Canva·Google Slides 만 되면 pptx 내보내기가 되는지 |
| 무료이거나 출처 표기만 하면 된다 | 학생 과제 | 라이선스 문구 |
| 한글이 어울린다 | 영문 글꼴이면 바꿔야 한다 | 쓰인 글꼴 이름. 한글 템플릿이면 더 좋다 |

검색은 영어와 한국어로 둘 다 한다. 한 곳에서 3개 이상 나오면 그 곳을 더 판다(같은 작가의 다른 템플릿, "비슷한 템플릿").

### 후보마다 할 일

1. 템플릿 페이지를 **직접 연다**. 미리보기 장을 끝까지 넘겨 본다.
2. 아래 표 한 줄을 채운다.
3. 장마다 2절의 컷 중 어디에 쓸 수 있을지 적어 둔다 (예: "7장 비교 → 5·13컷").

`ppt/템플릿_후보.md` 표 형식:

| # | 이름(링크) | 곳 | 값·라이선스 | 받는 형식 | 장 수 | 색 | 사진 정도 | 휴대폰 틀 | 큰 글자 | 비교 | 단계 | 큰 숫자 | 칸 구성 | 장식이 그림/도형 | 글꼴 | 점수 | [확인]/[추측] | 메모 |

점수는 5점 만점 6항목의 합(30점)이다.

| 항목 | 5점 | 1점 |
|---|---|---|
| 빈 공간·사진 적음 | 사진 거의 없음 | 장마다 사진 |
| 색 | 파랑 계열이거나 도형이라 바꾸기 쉬움 | 다른 색이고 그림이라 못 바꿈 |
| 필요한 장 (휴대폰·큰 글자·비교·단계·큰 숫자) | 5종 다 있음 | 1종 이하 |
| 받기 | 무료 pptx 바로 | 유료이거나 pptx 불가 |
| 한글 | 한글 템플릿이거나 글꼴만 바꾸면 됨 | 영문 장식 글자가 그림에 박혀 있음 |
| 발표와의 어울림 | 서비스·앱 소개 느낌, 차분함 | 장난스럽거나 업종이 너무 다름 |

### 추리기와 보고

- 점수 상위에서 **서로 다른 느낌으로 5개**를 고른다 (모두 비슷한 파랑 미니멀이면 하나를 다른 방향으로 바꾼다).
  - 예: 밝은 미니멀 / 어두운 바탕 / 칸 구성 / 한글 템플릿 / 템플릿 없이 사이트 색으로 직접 그리기
- 5개마다 `ppt/템플릿_후보.md` 맨 위에 다음을 적는다.
  - 왜 골랐나 (두세 줄)
  - 2절 컷 15개 중 어느 장으로 몇 컷을 채울 수 있나. 못 채우는 컷은 도형으로 그려야 한다
  - 걸리는 점
- 휴대폰 틀은 따로 3개 이상 고른다 (템플릿에 없을 때 붙일 것).
- 다 되면 커밋·push 하고, **사용자에게 5개 링크를 보여 주고 고르게 한 뒤 멈춘다.** 사용자가 고르기 전에 2단계로 넘어가지 않는다.

## 3. 2단계 이후 (템플릿이 정해진 뒤)

지난번과 같은 순서다. 자세한 건 [PPT_제작계획.md](PPT_제작계획.md) 0절.

1. **대본**: 18 텍스트에서 말로 하는 글을 뽑는다. `ppt/발표대본.md`. 발표 시간은 사용자에게 묻는다 (아직 모름). 사용자가 고친다.
2. **컷 계획 확정**: [PPT_제작계획.md](PPT_제작계획.md) 2절 표를 대본에 맞춰 고친다. 템플릿을 보기 전에 정한다.
3. **2단계 표**: 컷마다 템플릿의 어느 장을 쓰고 무엇을 고칠지, 비교했다가 뺀 장까지 적는다 ([참고 계획](참고/린스타트업_PPT_제작계획.md) 2단계 표와 같은 모양).
4. **화면 캡처**: 사이트를 Playwright 로 찍는다. 저장소 맨 위에서 `python3 -m http.server` 로 띄우고 `/site/` 를 연다. 휴대폰 390×844, PC 1280×860. 시험용 설정(예: `?dept=약학과`)으로 찍어 매번 같은 화면이 나오게 한다. 찍는 방법은 [../tests/ui_check.py](../tests/ui_check.py) 를 본다. 캡처는 `ppt/captures/` (공개돼도 되는 화면만).
5. **만들기**: [참고/ppt_build/lib.py](참고/ppt_build/lib.py) 를 `ppt/ppt_build/` 로 복사해 쓴다. `build.py` 는 린스타트업용 본보기다. 템플릿 pptx 를 풀어 장을 복제하고 글상자를 고친다. 그림이라 안 되는 곳은 도형을 새로 그린다. 템플릿 파일은 `ppt/templates/` (git 제외). 웹 환경에서 공식 링크로 직접 받을 수 없으면, 만들기는 로컬 Claude Code 에서 한다고 적고 멈춘다.
6. **렌더링 확인**: `sudo apt-get install -y libreoffice-impress fonts-noto-cjk poppler-utils` → `soffice --headless --convert-to pdf` → `pdftoppm -png -r 60`. 장마다 이미지를 직접 보고 원칙 파일의 점검표를 확인한다. 글꼴은 Pretendard 를 받아 설치하거나, 없으면 Noto Sans KR 로 보이는 것을 감안한다.
7. **고친 점 기록**: [PPT_제작계획.md](PPT_제작계획.md) 에 "PPTX 를 보고 고친 점 (날짜)" 절을 만든다.

## 4. 사용자에게 물어야 하는 것 (혼자 정하지 않는다)

- 템플릿 고르기 (1단계 끝)
- 발표 시간
- 시연: 실제 사이트를 띄울지, 녹화로 넣을지
- 표지에 발표자 이름을 넣을지
- 유료 템플릿을 살지

## 5. 웹 세션에 붙여 넣을 첫 메시지

```
ppt/웹_작업지침.md 를 읽고 그대로 해 줘. 먼저 git pull.
1단계(템플릿 찾기)만 한다: 지침의 모든 곳을 들러 후보 30개 이상을 직접 열어 보고,
ppt/템플릿_후보.md 에 20개 이상을 표로 적고 5개를 추려 줘. 휴대폰 틀도 따로 3개.
템플릿 파일과 미리보기 그림은 커밋하지 말고 링크만. 끝나면 커밋·main 에 push 하고 5개 링크를 보여 준 뒤 멈춰.
```
