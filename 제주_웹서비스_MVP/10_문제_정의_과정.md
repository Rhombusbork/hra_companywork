# 10. 고객 문제를 어떻게 정했나 — 지금까지 고민한 것

보고서(서비스 기획서)의 "문제 정의"를 쓰기 위한 바탕 자료다. 11/20 과제를 받은 날부터 11/26 까지 우리가 무엇을 기준으로 삼았고, 어떤 순서로 좁혔고, 왜 웹서비스로 풀 문제라고 봤는지를 날짜순으로 모았다.

모은 곳은 이렇다.

- 이 저장소의 00~09, 11 문서와 커밋 기록 (11/24~25 웹 세션 커밋 포함)
- 옮기기 전 `working_system` 의 `jeju-web-mvp` 브랜치 기록 (11/20~22)
- 로컬 Claude Code 대화 기록 (11/20 working_system, 11/21~23 비서, 11/26 이 저장소)
- 아직 `main` 에 합치지 않은 로컬 작업 폴더의 12~15 초안 (11/26, 사용자 테스트·피드백 분석표·기획서·개선 제안)

웹 세션(11/24~25)의 대화 원문은 이 PC 에 없다. 그때 정한 것은 06 에 남은 기록과 커밋으로만 알 수 있다. 그중 어느 것을 조원이 했고 어느 것을 내가 했는지는 기록으로 가릴 수 없다.

## 1. 과제가 요구한 것

과제 원문은 [00](00_과제_정리.md)에 옮겨 두었다. 캡처 원본은 교수진 이름이 있어 `_private/` 에만 있다.

문제와 관련된 줄만 다시 보면 이렇다.

- 개요: 제주 지역의 관광, 로컬 상품, 음식, 체험, 이동, **생활정보** 등과 관련된 **고객 불편을 하나** 선정한다.
- 학습 목표 첫 줄: **고객 문제를 정의하는 방법을 익힌다.**
- 평가지표 첫 줄: **문제 정의의 명확성.** 그 뒤로 MVP 기능의 적절성, 사용 편의성, 문제 해결 만족도, 재사용 의향.
- 주의 사항: 로그인·결제·DB 는 요구하지 않는다. 완성도보다 **고객 문제를 해결하는 최소 기능**.

그래서 처음부터 기능이 아니라 문제를 먼저 고르기로 했다(11/20, [01](01_좋은_문제란_책의_의견.md) 머리말).

## 2. 11/20 — "좋은 문제"의 기준부터 세움

과제를 받은 날 처음 물은 것은 이것이었다.

> 웹서비스를 통해 해결할 수 있는 좋은 문제에는 개념적으로 어떤 문제들이 있어? 책 등의 의견을 정리해줘. 경영적으로 웹서비스는 주로 어떤 문제 해결을 위해 활용되어?

### 2-1. 책에서 가져온 기준 ([01](01_좋은_문제란_책의_의견.md))

| 책 | 가져온 생각 |
|---|---|
| 에릭 리스 『린 스타트업』 (11/7 내가 발표한 책) | 아무도 원하지 않는 걸 잘 만드는 게 가장 큰 낭비. 가치 가설 = 문제 해결 만족도, 재방문 = 재사용 의향 |
| 애시 모리아 『Running Lean』 | 문제 칸과 **기존 대안**을 먼저 적는다. 대안이 아무것도 없으면 문제가 아닐 수도 있다 |
| 롭 피츠패트릭 『The Mom Test』 | 아이디어를 묻지 말고 **과거에 실제로 한 일**을 묻는다 |
| 크리스텐슨 『일의 언어』 | "어떤 상황에서, 무엇을 하려는데, 무엇이 막는가"가 한 문장으로 나와야 한다 |
| 도널드 밀러 『무기가 되는 스토리』 (같은 12/12 수업일 경영서) | 문제는 외적·내적·철학적 세 겹 |
| 사보이아 『아이디어 불패의 법칙』 | 가설을 "적어도 X%의 Y가 Z할 것이다"로 쓴다 → 피드백 정량화 |
| 폴 그레이엄 「How to Get Startup Ideas」 | 만드는 사람이 직접 겪는 문제, 소수가 깊이 원하는 문제 |
| 피터 틸 『제로 투 원』 | 작은 시장을 완전히. 타깃을 좁게 |
| 『스프린트』, 닐슨 | 5명이면 사용성 문제 약 85%가 드러난다 (과제의 5명 테스트와 맞음) |
| 니르 이얄 『훅』 | 자주 겪는 문제여야 습관이 된다 → 재사용 의향 |
| 카노 모델 | 핵심 기능은 당연 품질 하나 + 매력 품질 하나면 충분할 때가 많다 |

### 2-2. 웹이 잘 푸는 문제의 유형 ([01](01_좋은_문제란_책의_의견.md) 2부, [02](02_경영에서_웹서비스의_쓰임.md))

거래비용(코스), 정보재(샤피로·배리언), 롱테일(앤더슨), 플랫폼(파커 외)에서 유형을 뽑았다.

- 잘 푸는 것: **정보가 흩어져 있다**, 찾기·비교가 어렵다, 판단·계산이 귀찮다, 정보 비대칭, **타이밍·상태를 모른다**, 절차가 복잡하다, 언어 장벽, 수요·공급이 못 만난다.
- 못 푸는 것: 물리적인 문제(길 막힘, 짐), 사람이 많이 모여야 가치가 생기는 문제(후기, 매칭), 규제·단속으로 풀 문제(바가지요금, 택시).
- 과제 조건(로그인·결제·DB 없음)이 오히려 범위를 정해 준다. **입력 → 결과** 한 번에 끝나는 것이 맞는다. 계산기, 추천기, 체크리스트, 비교표, 조건 필터, 정보 모음.

경영 쪽에서 보면 기업은 웹서비스로 인지·판매 채널·응대 비용·고객 유지·운영 효율·데이터·새 사업 모델 문제를 푼다(포터 「Strategy and the Internet」). 여기에 『린 스타트업』의 **아이디어 검증 도구**가 하나 더 있고, 이번 MVP 가 바로 그 용도다.

### 2-3. 한 줄 정의 ([04](04_핵심_정리.md))

같은 날 "내가 원하는 방향성 및 웹서비스로 해결하기 좋은 문제의 정의"를 한 장으로 줄였다.

> **특정한 사람이 자주 겪고, 지금은 불편한 방법으로 버티고 있으며, 정보를 입력하면 결과 화면 하나로 풀리는 문제.**

조건 여섯 개: 누가 겪는지 분명하다 / 실제로 겪었다 / 지금 버티는 방법(기존 대안)이 있다 / 자주 겪는다 / 정보 문제다 / 입력 → 결과로 끝난다.

문장 틀(『일의 언어』 + 『무기가 되는 스토리』):

> [누가]는 [어떤 상황]에서 [무엇을 하려는데], [무엇] 때문에 막힌다. 그래서 [어떤 기분]이 든다.

### 2-4. 처음 후보는 관광이었다 ([03](03_문제_찾기_방법.md))

내가 처음 말한 방향은 이랬다.

> 실제 문제를 찾고 싶어. 일단 참고할 수 있는 게 블로그 여행후기, 지방자치단체 민원, 그리고 실제 의견에서는 아는 형이 제주의 문화 관광지가 정리된 프로그램이 없대. 근데 또 실질적으로 진짜 문제인 지 발로 뛰며 조사할 수 있는 방법은 없나? 전화해볼 곳이나?

그래서 03 에 "진짜 문제" 확인 방법을 정리했다.

- 책상에서: 블로그·지도 리뷰의 후회·불편 문장 30개를 유형별로 세기, 관광불편신고 집계(공공데이터포털), 국민신문고, 정보공개청구, 제주 방문관광객 실태조사, 「데이터로 보는 제주여행 — 크루즈편」.
- 발로: 공항 관광안내소·제주관광정보센터에 전화, 박물관 매표소·문화관광해설사, 게스트하우스 사장님, 제주대 학생.
- 묻는 법: 내 아이디어는 말하지 않고 "가장 자주 묻는 질문", "최근 기억나는 손님 이야기", "지금은 무엇을 보여 주며 안내하는지".
- 판단: 블로그 / 민원·조사 / 안내하는 사람 / 기존 대안 / 테스트할 5명 / 입력 → 결과 중 **세 가지 이상** 맞으면 고른다.

형의 말도 먼저 따져 봤다. 비짓제주·플레이제주·젠트립이 이미 있고, 제주 박물관·미술관은 2016년 등록 83곳 중 66곳이 사립이었다(서울신문 2016, 오래된 자료). 그래서 형이 겪은 문제가 **없다 / 못 고른다 / 틀렸다(휴관·운영시간)** 중 무엇인지부터 가려야 한다고 적었다.

## 3. 11/21 — 제주대 정보로 바꿈

다음 날 방향을 바꿨다. 내가 한 말은 이렇다([05](05_내_아이디어.md)).

> 내가 다니는 제주대학교 관련 장학금, 행사 등의 정보를 모아 한번에 보여주는 웹사이트를 서비스하고 싶어. 특히 그 사람이 원하는 것이 정해져 있을 때 미리 말해 놓으면 그것과 관련된 것들만 계속 모으고 보여준다던지, 필요한 거 여러 사이트에 나누어져 있는 정보들을 한번에 모아 보여준다던지 하는 서비스.

관광 쪽 조사(전화, 정보공개청구, 형 인터뷰)를 해 보고 바꾼 것인지, 그 전에 바꾼 것인지는 기록에 없다. **바꾼 이유를 보고서에 쓰려면 직접 적어 넣어야 한다.** 다만 04 의 기준에 대 보면 이렇게 맞는다(05 에 적어 둔 것).

| 04 의 조건 | 관광(형의 말) | 제주대 정보 |
|---|---|---|
| 누가 겪는지 분명하다 | 관광객, 좁혀도 "문화시설 찾는 여행객" | 제주대 학생. 좁히면 장학금을 찾는 학생 |
| 실제로 겪었다 | 형 한 명의 말. 확인 전 | 나 자신이 겪는다 (폴 그레이엄) [추측: 05 에 "내가 다니는"이라고만 있음] |
| 기존 대안이 있다 | 비짓제주, 검색, 지도 | 학교·학과·장학 게시판을 따로 들어가 보기, 카톡방 공지 |
| 자주 겪는다 | 여행할 때만, 1년에 몇 번 | 학기마다, 매주 |
| 정보 문제다 | 못 고른다 / 틀렸다 중 무엇인지 모름 | 흩어짐 + 놓침 |
| 입력 → 결과 | 조건 → 추천 | 관심사 → 모은 글 |
| 5명 테스트 | 여행 온 사람을 찾아야 함 | 약학과·HRA 동기 |

과제 개요의 "생활정보"에 제주대 학생의 생활정보로 들어간다고 봤다.

## 4. 11/21~22 — 정말 흩어져 있는지 조사

이 문제는 "정보가 흩어져 있다"가 핵심이라, 정말 그런지를 먼저 셌다. 내가 부탁한 범위는 넓었다.

> 제주대학교 관련 정보를 모을 수 있는 사이트들을 모두 찾고, 그 중 양질의 정보들을 모은 뒤, 정리해주면 좋겠어. … 다양한 과 홈페이지에만 올라오는 공지도 모아줄 수 있으면 좋을 거 같고.

에이전트 다섯이 각기 다른 방법으로 찾았고(정보원_조사 01~05), 웹 세션에서 [07](07_정보원_종합.md)로 합친 뒤 핵심 주소 21개를 직접 받아 확인했다. 11/22 에 학과 101곳 전수표([02-1](정보원_조사/02-1_학과_전수표.md))를 더했다.

문제 정의에 바로 쓸 수 있는 사실들이다.

- 공지가 흩어진 곳: 본부 공지, 학과 게시판(공지 주소가 있는 곳 92곳), 학생생활관, 진로취업(clip), 국제교류, 제대로 산학1번지(jedaero), 중앙도서관. 학교 밖까지 보면 제주청년센터 등 45곳 [확인].
- 본부 공지는 2주에 76건. 그중 장학 4건(10/12~11/18 사이엔 약 20건) [확인, 01].
- 장학 공고의 마감일은 목록에 칸이 없다. 제목이나 첨부 안에만 있다. 마감일이 칸으로 있는 곳은 jedaero 하나다 [확인].
- 학과 게시판에만 올라오는 글이 있다. 학과 국가근로장학생 선발, 대학원 복지장학, 튜터링, 트랙 선발, 졸업 신청, 학부 시간표, 병원 약사·간호사 채용 [검색, 02]. 단과대 첫 화면도 학과 글을 모아 주지 않는다 [확인].
- 같은 글이 여러 곳에 다시 올라온다. 자매국수 장학 글이 본부 282814, 약학대학 282815, 간호학과 282825 로 번호가 다 달랐다 [확인]. 학생 입장에선 같은 글을 여러 번 보거나, 내 학과 게시판만 보다 본부 글을 놓친다.
- 학식도 흩어져 있다. 백두관·사라는 학교 페이지, 6호관은 학교 페이지가 늦게 바뀌고 업체 게시판에 먼저 올라온다, 1호관 점심·저녁은 인스타그램 이미지에만 있다 [확인, 03·07].
- 막힌 곳도 셋: 1호관 인스타, 비교과 신청(포털 로그인), 에브리타임(로그인·약관).

조사하면서 함께 정한 선도 있다. 학교 사이트는 robots.txt 가 전체 차단이라, 목록 첫 페이지만 하루 2~4회, 요청 사이 2~3초, 모든 글에 원문 링크, 본문·작성자는 저장 안 함(07 5절).

## 5. 11/24~25 — 누구에게 무엇을 보여 줄지 (웹 세션)

조사가 끝난 뒤 웹 세션에서 화면 방향을 정했다. 06 의 기록과 커밋에서 옮긴다.

- 11/24 선택 화면.
  - 원하는 것만 보이게 볼 것을 고르는 창, 학과·복수전공 선택, 고른 학과 글을 위에.
  - 어문 계열은 교환학생·어학연수를 제안하는 식으로 계열별 추천.
  - **장학은 필수가 아니고 선택사항 맨 위.** 차별점은 "국가장학금은 기존 앱으로 충분하니, 우리는 학교·학과·재단 장학만 모은다."
  - 푸시 알림은 서버가 없어 안 된다 → 화면 안 "새 글"·"마감 임박"으로 대신.

## 6. 11/26 — 진짜 문제인지 확인하는 법, 첫 화면 다시 정함

과제가 "제대로 된 문제와 해결"을 찾으라고 해서, 이게 진짜 사람들에게 문제인지 아는 법을 다시 물었다. 답으로 받은 것은 03 의 방법을 제주대 쪽으로 옮긴 것이다.

1. **남아 있는 흔적**: 에브리타임·학과 단톡방에서 "장학금 언제까지", "공지 어디서 봐", "학식 뭐야" 같은 질문이 반복되는지. "마감 지나서 알았다" 글 하나가 설문 10개보다 강하다. 실명은 가리고 `_private/` 에만.
2. **과거의 사실을 묻기** (Mom Test): "최근에 장학금이나 공지를 놓친 적 있어? 그때 어떻게 알게 됐어?", "공지 확인하려고 마지막으로 어디 들어갔어? 몇 군데 봤어?" 같은 불편이 3명 넘게 나오면 문제로 볼 만하다.
3. **만들어서 반응 보기**: Pages 링크를 뿌리고 다시 들어오는지, 북마크·공유하는지.
4. **숫자로 크기**: 공지 보려면 몇 개 사이트인지(02-1), 한 달 장학 공지 수와 신청 기간.

경쟁자는 다른 앱보다 **"그냥 단톡방에 물어보기"**라는 말도 이때 나왔다. 그보다 빨라야 쓴다. 학식처럼 매일 볼 것이 다시 오게 하는 갈고리가 된다는 것도.

같은 날 첫 화면을 바꿨다. 내가 한 말:

> 내 생각에 학과 선택부터 있으면 귀찮아서, 건너뛰기 하고 나오는 게 기본 옵션이고 학과를 원하면 넣을 수 있게 하는 게 더 좋을 거 같아.

→ 처음 들어오면 바로 홈(전체 보기), 학과는 원하는 사람만 넣는다(06). 11/24 의 "선택 창 먼저"를 뒤집은 것이다. 사용자 테스트에서 "학과를 넣었는지, 왜 안 넣었는지" 물으면 이 결정의 근거가 된다.

로컬 작업 폴더의 12~15 초안(아직 `main` 에 없음)에는 사용자 테스트 질문지, 피드백 분석표 틀, 기획서·개선 제안 초안이 있다. 기획서 초안의 문제 문장:

> 제주대 학생은 장학금·행사·학과 공지를 챙기려는데, 공지가 본부·학과·생활관·진로취업센터·국제교류처에 흩어져 있고 마감일이 제목이나 첨부 안에만 있어서 놓친다.

## 7. 왜 웹서비스로 풀기 좋은 문제라고 봤나

01·04 의 기준을 하나씩 대 본다.

| 기준 | 이 문제 | 근거 |
|---|---|---|
| 정보 문제다 | 정보가 흩어져 있고(유형 1), 마감을 모른다(유형 5 타이밍) | 07 1절, 4절 위 |
| 물리·규제 문제가 아니다 | 글은 이미 공개돼 있다. 모아서 거르기만 하면 된다 | 공지 목록은 로그인 없이 열림 [확인] |
| 사람이 모여야 가치가 생기지 않는다 | 첫 사용자 한 명도 바로 쓸모를 본다. 후기·매칭이 아니다 | 01 2부 |
| 입력 → 결과로 끝난다 | 학과·관심사(입력) → 모은 글·마감 순(결과) | 09 입력 항목·결과 화면 |

| 기능 2~3개로 풀린다 | 모아 보기 / 마감 표시 / 내 학과 | 14 초안 4절 |
| 자주 겪는다 | 장학 주 3~5건, 학식은 매일 | 01 조사 [확인] |
| 5명을 찾을 수 있다 | 약학과·HRA 동기 | 05 |
| 웹이라 나은 점 | 링크 하나로 열린다, 설치가 없다, 휴대폰·PC 모두 | [추측] |

경영 쪽으로 한 줄 쓰면(02 의 연결): 학생 쪽에선 **탐색비용**을 줄이고, 학교 쪽에선 같은 질문에 답하는 **응대 비용**을 줄이는 셀프서비스에 가깝다 [제안].

『무기가 되는 스토리』의 세 겹으로 나눠 보면 [제안]:

- 외적: 공지가 여러 곳에 흩어져 있고 마감일이 첨부 안에 있다.

- 철학적: 받을 수 있었던 장학금을 몰라서 못 받는 일은 없어야 한다.

## 8. 아직 비어 있는 것 (보고서 쓰기 전에)

- **사람에게서 나온 근거가 아직 없다.** 지금까지의 근거는 모두 "정보가 흩어져 있다"는 사이트 조사다. 학생들이 실제로 놓쳤는지는 아직 확인하지 않았다. 에타·단톡 흔적 모으기와 5명 인터뷰가 남아 있다(11 의 사람이 할 일). 평가지표 첫 줄이 문제 정의라 여기가 가장 약하다.
- 관광 → 제주대로 바꾼 이유를 내 말로 한 줄 적어야 한다.
- 관광 쪽에서 계획한 전화·정보공개청구·형 인터뷰를 실제로 했는지 기록이 없다. 했다면 결과를, 안 했다면 "방향을 바꿔 하지 않았다"를 적는다.
- 타깃을 한 명으로 더 좁힐지(신입생? 장학금 찾는 학생? 기숙사생?).
- 자리있수다와 비교해서 왜 이쪽을 골랐는지(조에서 정했다면).
- 03 일정의 "11/27(금) 조 회의에서 문제 하나 정하기"가 아직 앞에 있다.
