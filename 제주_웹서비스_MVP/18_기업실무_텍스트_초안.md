[ Ⅰ. 고객 문제 정의 ]

1. 과제와 "좋은 문제"의 기준

과제는 제주 지역의 관광, 로컬 상품, 음식, 체험, 이동, 생활정보와 관련된 고객 불편을 하나 골라 간단한 웹서비스 MVP 로 푸는 것이다. 평가지표의 첫 줄이 문제 정의의 명확성이고, 주의 사항에는 완성도보다 고객 문제를 해결하는 최소 기능에 집중하라고 적혀 있다. 그래서 기능보다 문제를 먼저 고르기로 했다.

1) 책에서 가져온 기준

| 책 | 가져온 생각 |
|---|---|
| 에릭 리스 『린 스타트업』 | 아무도 원하지 않는 것을 잘 만드는 것이 가장 큰 낭비다. 가치 가설은 문제 해결 만족도, 재방문은 재사용 의향으로 잰다 |
| 애시 모리아 『Running Lean』 | 문제와 함께 기존 대안을 먼저 적는다. 대안이 아무것도 없으면 문제가 아닐 수도 있다 |
| 롭 피츠패트릭 『The Mom Test』 | 아이디어를 묻지 말고 과거에 실제로 한 일을 묻는다 |
| 크리스텐슨 『일의 언어』 | "어떤 상황에서, 무엇을 하려는데, 무엇이 막는가"가 한 문장으로 나와야 한다 |
| 도널드 밀러 『무기가 되는 스토리』 | 문제는 외적·내적·철학적 세 겹이다 |
| 『스프린트』, 닐슨 | 5명이면 사용성 문제의 약 85%가 드러난다 |

2) 웹이 잘 푸는 문제

거래비용, 정보재, 롱테일, 플랫폼에 관한 책에서 유형을 뽑았다. 정보가 흩어져 있거나, 찾기·비교가 어렵거나, 타이밍을 모르는 문제는 웹이 잘 푼다. 길이 막히는 것 같은 물리적인 문제, 후기·매칭처럼 사람이 많이 모여야 가치가 생기는 문제, 바가지요금처럼 단속으로 풀 문제는 잘 못 푼다. 로그인·결제·DB 가 없다는 과제 조건은 오히려 범위를 정해 주었다. 정보를 넣으면 결과 화면 하나로 끝나는 것이 맞는다.

3) 한 줄 정의

- 특정한 사람이 자주 겪고, 지금은 불편한 방법으로 버티고 있으며, 정보를 입력하면 결과 화면 하나로 풀리는 문제.
- 문장 틀: [누가]는 [어떤 상황]에서 [무엇을 하려는데], [무엇] 때문에 막힌다. 그래서 [어떤 기분]이 든다.

2. 관광에서 제주대 정보로 좁힌 과정

1) 처음 후보는 관광이었다

처음에는 아는 형이 "제주의 문화 관광지가 정리된 프로그램이 없다"고 한 말에서 출발했다. 진짜 문제인지 확인하려고 블로그 후기의 불편 문장 세기, 관광불편신고 집계, 관광안내소·박물관 매표소에 전화하기 같은 방법을 정리했다. 그런데 비짓제주·플레이제주 같은 서비스가 이미 있었고, 형이 겪은 문제가 "없다"인지 "못 고른다"인지 "휴관·운영시간이 틀렸다"인지부터 가려야 했다.

2) 제주대 정보로 바꿨다

다음 날 방향을 바꿨다. 그때 한 말은 이렇다.

"내가 다니는 제주대학교 관련 장학금, 행사 등의 정보를 모아 한번에 보여주는 웹사이트를 서비스하고 싶어. 특히 그 사람이 원하는 것이 정해져 있을 때 미리 말해 놓으면 그것과 관련된 것들만 계속 모으고 보여준다던지."

(채울 곳: 관광에서 제주대로 바꾼 이유를 직접 한 줄)

과제 개요의 "생활정보"에 제주대 학생의 생활정보로 들어간다고 보았다. 앞의 기준에 대 보면 이렇다.

| 기준 | 관광 | 제주대 정보 |
|---|---|---|
| 누가 겪는지 | 관광객, 좁혀도 문화시설 찾는 여행객 | 제주대 학생. 좁히면 장학금을 찾는 학생 |
| 실제로 겪었나 | 형 한 명의 말, 확인 전 | 직접 다니는 학교 |
| 기존 대안 | 비짓제주, 검색, 지도 | 학교·학과 게시판을 따로 들어가 보기, 단톡방 공지 |
| 얼마나 자주 | 여행할 때만 | 학기마다, 매주 |
| 5명 테스트 | 여행 온 사람을 찾아야 함 | 약학과·HRA 동기 |

3. 정말 흩어져 있는지 조사한 결과

이 문제는 "정보가 흩어져 있다"가 핵심이라, 정말 그런지를 먼저 셌다. AI 에이전트 다섯이 각기 다른 방법으로 제주대 정보원을 찾았고, 그중 핵심 주소 21개는 직접 받아 확인했다. 학과 홈페이지 101곳도 전수조사했다.

- 공지가 올라오는 곳: 본부 공지, 학과 게시판(공지 주소가 있는 곳 92곳), 학생생활관, 진로취업센터, 국제교류, 제대로 산학1번지, 중앙도서관. 학교 밖까지 보면 45곳이다.
- 본부 공지는 2주에 76건이고, 그중 장학은 4건이었다.
- 장학 공고의 마감일은 목록에 칸이 없다. 제목이나 첨부 안에만 있다. 마감일이 칸으로 있는 곳은 제대로 산학1번지 하나다.
- 학과 국가근로장학생 선발, 졸업 신청, 학부 시간표처럼 학과 게시판에만 올라오는 글이 있다. 단과대 첫 화면도 학과 글을 모아 주지 않는다.
- 같은 글이 여러 곳에 다시 올라온다. 한 장학 글이 본부, 약학대학, 간호학과에 글 번호가 다 다르게 올라와 있었다.
- 학식도 흩어져 있다. 백두관·사라는 학교 페이지, 6호관은 업체 게시판에 먼저 올라오고, 1호관 점심·저녁은 인스타그램 이미지에만 있다.

4. 사람에게서 나온 근거

3절은 "사이트가 흩어져 있다"는 조사뿐이다. 학생이 실제로 몰랐거나 놓쳤다는 근거는 웹에서 찾았다. 에브리타임은 로그인이 필요해 검색에 나오지 않았고, 제주대 학내 언론에서 이 문제를 다룬 기사도 찾지 못했다.

| 자료 | 내용 |
|---|---|
| 서강동문장학회 재학생 인식조사 (2020, 학부생 352명) | 장학금 미신청자의 약 40%가 "해당 장학금이 있는지 몰랐다"고 답했다 |
| 베리타스알파 (2019), 감사원 2018 결산감사 설문 인용 | 국가장학금 미신청자 대부분이 제도 자체나 신청기간·방법을 몰랐다 |
| 동덕여대학보 (2023), 학식 앱을 만든 학생 인터뷰 | "학교 포털사이트 공지사항에도 좋은 공고들이 많이 올라오는데 저는 많이 놓쳤었거든요." |

학생들이 직접 만든 해결책도 있었다. 동양미래대 DMforU, 인하대 인하공지, 광운대 KW 알리미처럼 다른 학교 학생들이 공지 모아 보기 앱을 만들었다. 제주대에도 2026년 11월 17일에 시작된 비공식 공지 모아보기 사이트가 있다. 다른 학생도 이 불편을 느껴 시간을 들여 직접 만들었다는 뜻이다. 다만 우리 서비스와 겹치므로 차이를 분명히 해야 한다.

한계도 있다. 위 자료는 모두 다른 학교나 오래된 자료라, 제주대 학생의 목소리는 아직 없다.

(채울 곳: 에브리타임·단톡방에서 찾은 글, 5명 인터뷰에서 나온 "놓친 적" 이야기)
(채울 곳: 제주대 비공식 공지 사이트와 우리 서비스의 차이)

5. 문제 정의와 타깃 사용자

1) 문제 정의

제주대 학생은 장학금·행사·학과 공지를 챙기려는데, 공지가 본부·학과·생활관·진로취업센터·국제교류처에 흩어져 있고 마감일이 제목이나 첨부 안에만 있어서 놓친다.

『무기가 되는 스토리』의 세 겹으로 나누면 이렇다.

- 외적: 공지가 여러 곳에 흩어져 있고 마감일이 첨부 안에 있다.
- 내적: 놓쳤을까 봐 불안하다. 알고 보니 마감이 지나 있어 허탈하다.
- 철학적: 받을 수 있었던 장학금을 몰라서 못 받는 일은 없어야 한다.

2) 타깃 사용자

- 주 타깃: 제주대 학부생
- 보조 타깃: 대학원생, 기숙사생, 복수전공·교직 이수 학생

경쟁자는 다른 앱보다 "그냥 단톡방에 물어보기"다. 그보다 빨라야 쓴다.

[ Ⅱ. 서비스 기획 ]

1. 서비스명과 핵심 가치

- 서비스명: 제주대 모아보기 (가칭)
- 핵심 가치: 제주대 공지·장학·학식을 한 화면에, 마감이 가까운 순으로. 로그인 없이. 원하면 내 학과를 넣어 학과 공지를 맨 위에 둔다.
- 차별점: 국가장학금은 기존 앱으로 충분하다. 우리는 학교·학과·재단 장학과 학과 게시판에만 올라오는 글을 모은다.

2. 핵심 기능

1) 한곳에 모아 보기

여러 게시판의 글을 분류 카드로 모은다. 카드는 학사, 장학, 생활관, 프로그램·행사, 취업·인턴, 국제교류다. 큰 카드는 적게 두고, 카드 안에서 칩으로 유형을 거른다. 예를 들어 학사 카드 안에는 수업·등록·학적·학사일정 칩이 있다. 학과가 본부 글을 다시 올린 것은 하나로 합친다.

2) 마감 표시

마감이 남은 글은 마감이 가까운 순으로, D-day 와 함께 보인다. 마감일 옆에는 그 날짜를 어디서 읽었는지 붙인다(게시판 칸 / 제목). 틀린 마감일은 없는 것보다 해롭기 때문이다.

3) 내 학과

원하는 사람만 학과를 넣는다. 넣으면 학과 게시판 글, 학과가 다시 올린 본부 글, 졸업요건·자격 글이 맨 위에 뜬다. 계열에 맞는 분류도 더해진다. 어문 계열이면 국제교류 카드가 추천되는 식이다.

그 밖에 오늘 학식, 북마크와 일정 달력, 제목 검색, 휴대폰 캘린더 구독(.ics)이 있다.

3. 사용자 입력 항목

처음 들어오면 아무것도 묻지 않고 바로 홈이 뜬다. 처음에는 볼 것을 고르는 창을 먼저 띄우려 했다. 그런데 학과 선택부터 나오면 귀찮아서 다들 건너뛸 것 같았다. 그래서 건너뛴 상태를 기본으로 두고, 학과는 원하는 사람만 넣게 바꿨다(11/26).

| 입력 | 필수 | 메모 |
|---|---|---|
| 주전공 | 선택 | 넣으면 학부/대학원·캠퍼스가 자동으로 채워지고 계열에 맞는 분류를 추천 |
| 복수전공·부전공 | 선택 | |
| 기숙사 여부 | 선택 | 생활관 카드 |
| 교직 이수 여부 | 선택 | 사범·교육 계열은 자동 |
| 볼 분류, 학식 식당 | 선택 | |
| 키워드 | 선택 | 모아 보기·숨기기 |

학년은 뺐다. 로그인이 없으니 3월이 되면 저장된 학년이 틀린다. 학년이 필요했는지는 테스트에서 묻는다.

4. 결과 화면

홈은 칸(위젯) 그리드다. 이번 주 한 줄, 오늘 학식, 내 학과, 장학·학사 같은 분류 칸이 있고, 사용자가 '홈 편집'으로 칸을 옮기고, 크기를 바꾸고, 숨기고, 색을 고른다. 배치는 그 사람 브라우저에만 저장된다. 글을 누르면 상세 창(게시일, 마감과 출처, 첨부 이름, 북마크)이 뜨고, 거기서 원문으로 간다. 화면 아래에는 "제주대 공식 서비스가 아님, 모든 글은 원문 링크"를 적었다.

| 온통청년 | 전공·지역으로 정책을 거른다 | 계열별 추천의 근거 |

다른 학교 앱들은 모두 푸시 알림을 앞세운다. 우리는 서버가 없어서 그걸 못 한다. 그래서 차이는 계열에 맞춘 추천과 학과 게시판 글 쪽에서 내야 한다.

[ Ⅲ. 바이브코딩으로 만든 MVP ]

1. 구조

서버와 DB 없이 돌아가게 만들었다.

- GitHub Actions 가 하루 4번(07·12·17·22시) 학교 게시판 첫 페이지를 읽어 JSON 파일로 만든다.
- GitHub Pages 가 그 파일을 보여 준다. 주소는 https://rhombusbork.github.io/hra_companywork/ 이다.
- 사용자의 학과·관심사·북마크는 그 사람 브라우저에만 저장된다.

| 과제 조건 | 어떻게 맞췄나 |
|---|---|
| 로그인 없음 | 아무 설정 없이 바로 쓴다. 설정은 브라우저에만 |
| 결제 없음 | 무료 |
| DB 없음 | 수집 결과는 JSON 파일. 저장소에 함께 들어간다 |
| 최소 기능 | 모아 보기 · 마감 표시 · 내 학과 |

지금 모으는 곳은 본부 공지, 학생생활관, 국제교류, 진로취업센터, 약학대학, 간호대학, 제대로 산학1번지, 중앙도서관, 제주청년센터, 학사일정, 학식 3곳(백두관·6호관·사라)이다. 학과 게시판은 약학·간호 두 곳으로 시작했고, 다른 학과를 고르면 "아직 모으지 않아요"와 게시판 링크를 보여 준다.

2. 만든 순서

코드는 거의 다 Claude Code 에게 말로 시켜 만들었다. 조원이 웹 Claude Code 와 로컬 Claude Code 로 번갈아 작업했고, 11/20 부터 11/27 까지 커밋이 64개 쌓였다.

| 날짜 | 한 것 |
|---|---|
| 11/20 | 좋은 문제의 기준 정리, 관광 쪽 확인 방법 |
| 11/21~22 | 제주대 정보로 방향 바꿈, 정보원 조사 5개와 종합, 학과 101곳 전수표 |

| 11/26 | 수집기와 하루 4번 자동 갱신, 첫 화면을 바로 홈으로, 시안 두 개를 하나로 합침 |
| 11/26 밤 | AI 가 백로그를 하나씩 고치는 루프: 학사일정 수집, 중복 정리, 검색, 홈 화면에 추가, 캘린더 구독, 화면 시험 41개 |

밤 루프는 규칙을 문서로 정해 두고 AI 가 한 바퀴마다 하나를 고치고 기록하게 한 것이다. 화면을 눌러 보는 시험을 먼저 만들고, 시험을 통과한 것만 합치게 했다.

3. 부딪힌 문제와 대응

1) 학교 사이트가 자동 수집을 막아 둠

학교 본부 사이트들은 robots.txt 가 전체 차단이다. 그래서 목록 첫 페이지만, 하루 2~4회, 요청 사이 2~3초를 두고 읽는다. 요청에 서비스 이름과 저장소 주소를 밝히고, 모든 글에 원문 링크를 단다. 본문과 작성자는 저장하지 않는다. 학교에 협조를 구하는 메일 초안도 써 두었다.

2) 학교 서버의 인증서

학교 서버가 중간 인증서를 보내지 않아 보안 연결이 실패했다. 검증을 끄지 않고, 중간 인증서를 따로 받아 함께 검증하게 했다.

3) 학교 쪽이 연결을 끊음

11/26 밤, 고칠 때마다 수집이 돌아 몇 분 간격으로 요청이 몰렸다. 그 직후부터 학교 CMS 사이트들이 연결을 끊었다. 11/27 아침 정기 수집에서도 본부·생활관·국제교류·진로취업·학과는 실패했다. 산학1번지·도서관·청년센터는 정상이다. 실패한 곳은 이전 글을 그대로 보여 주고, 자동으로 이슈가 열린다. 고칠 때 수집이 돌지 않게 바꿨다.

(채울 곳: 발표 전까지 풀렸는지)

4) 1호관 학식

1호관 점심·저녁 메뉴는 인스타그램 이미지에만 있다. 업체 사이트의 인스타 위젯도 확인했지만 글 칸이 모두 비어 있었다. 그래서 링크만 둔다.

[ Ⅳ. 사용자 피드백과 개선 제안 ]

1. 테스트 방법

1) 진행

- 제주대 학생 5명 이상, 단과대가 섞이게.
- 휴대폰으로, 링크만 주고 설명하지 않는다. 옆에서 지켜보며 어디서 멈추는지 적는다.
- 순서: 인터뷰(사이트 보여 주기 전) → 과제 시나리오 → 폼 작성. 한 사람에 15분 안팎.
- 이름·학번은 적지 않는다.

2) 인터뷰

"이런 서비스 있으면 쓰겠어?"는 묻지 않는다. 예의상 "응"이라고 답하기 때문이다. 대신 지난 일을 묻는다.

- 최근에 장학금·행사·학과 공지를 늦게 알았거나 놓친 적이 있어? 언제였어?
- 그때 어떻게 알게 됐어?
- 학교 공지를 확인하려고 마지막으로 들어간 곳이 어디야? 몇 군데 봤어?
- 학식은 어떻게 확인해?

3) 과제 시나리오

| 번호 | 과제 | 보는 것 |

3. 개선 제안

테스트 전이라 순위는 비워 두었다. 테스트에서 많이 나온 문제부터 순위를 매긴다.

1) 이미 반영한 것

처음에 개선 제안으로 적었다가 만들면서 넣은 것들이다. 제목 검색, 휴대폰 홈 화면에 추가, 마감·학사일정 캘린더 구독(.ics), 분류·학과별 RSS, 제주청년센터 소식, 수집이 실패하면 자동으로 이슈 열기.

2) 정보를 더 정확하게

- AI 첨부 읽기: 장학 공지는 마감일이 첨부(PDF·이미지)에만 있는 경우가 많다. 새 글의 첨부를 하루 한 번 AI 로 읽어 마감일과 세 줄 요약을 채운다. 결과·명단·합격 글은 개인정보 때문에 읽지 않는다. 화면엔 "AI 추정, 원문에서 꼭 확인"을 붙인다. API 비용이 들고, 학교 협조 메일을 먼저 보내는 것이 맞다.
- 1호관 학식: 업체에 주간 메뉴를 홈페이지 게시판에 글로 올려 달라고 부탁한다. 아침 메뉴는 이미 그렇게 올리고 있다.

3) 정보를 더 넓게

- 학과 확대: 약학·간호 → 테스트한 학생들의 학과 → 전체 92곳.
- 학교와 공식 협조: 메일로 알리고 RSS·공식 데이터를 문의한다.
- 학교 밖: 한국장학재단 자료, 청년정책 API.

4) 쓰기 편하게

- 알림: 카카오톡 채널이나 텔레그램 봇으로 새 글·마감 임박을 보낸다. 보내는 서버가 필요하다.
- 시간표 연동: 내 수업 공지만 보기. 로그인이 필요해 이번 과제 조건과는 맞지 않는다.
- "덜 보기": 글마다 "이런 글 덜 보기".
