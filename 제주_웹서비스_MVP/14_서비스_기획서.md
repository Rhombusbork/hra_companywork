# 14. 서비스 기획서 (초안)

과제 산출물 "서비스 기획서" 초안이다. 순서는 [00](00_과제_정리.md)의 할 일 순서를 따랐다. 내용은 [09 서비스 요약](09_서비스_요약.md)과 [07](07_정보원_종합.md)에서 가져왔다. 문제 근거 칸은 테스트와 조사를 마친 뒤 채운다.

## 1. 서비스명과 핵심 가치

- 서비스명: **제주대 모아보기** (가칭)
- 핵심 가치: 제주대 공지·장학·학식을 한 화면에, 마감이 가까운 순으로. 로그인 없이. 원하면 내 학과를 넣어 학과 공지를 맨 위에 둔다.
- MVP 링크
  - v1: https://rhombusbork.github.io/hra_companywork/
  - v2 (상세 창·북마크 사이드바): https://rhombusbork.github.io/hra_companywork/v2/

## 2. 고객 문제

> 제주대 학생은 장학금·행사·학과 공지를 챙기려는데, 공지가 본부·학과·생활관·진로취업센터·국제교류처에 흩어져 있고 마감일이 제목이나 첨부 안에만 있어서 놓친다.

- 공지는 흩어져 있다. 본부 공지, 학과 게시판(92곳), 학생생활관, 진로취업센터(clip), 국제교류처, 제대로 산학1번지, 중앙도서관이 따로 있다([07](07_정보원_종합.md) 1절, [02-1](정보원_조사/02-1_학과_전수표.md)).
- 장학 공고는 일주일에 4건쯤 올라온다. 마감일은 제목이나 첨부 파일 안에만 있다([09](09_서비스_요약.md)).
- 학과 근로장학생 모집, 졸업시험 안내처럼 학과 게시판에만 올라오는 글이 있다. 단과대 첫 화면도 학과 글을 모아 주지 않는다([07](07_정보원_종합.md) 3절).
- 학식도 식당마다 올리는 곳이 다르다. 6호관은 학교 페이지가 늦게 바뀐다([07](07_정보원_종합.md) 2절).

## 3. 타깃 사용자

- 주 타깃: 제주대 학부생
- 보조 타깃: 대학원생, 기숙사생, 복수전공·교직 이수 학생

## 4. 핵심 기능

1. **한곳에 모아 보기**: 여러 게시판의 글을 분류 카드(학사·장학·생활관·프로그램·행사·취업·인턴·국제교류)로 모으고, 카드 안에서 칩으로 유형을 거른다.
2. **마감 표시**: 마감이 남은 글은 마감 가까운 순. D-day 옆에 마감일을 어디서 읽었는지 붙인다(게시판 칸 / 제목 / AI 추정).
3. **내 학과**: 원하는 사람만 학과를 넣는다. 넣으면 학과 게시판 글, 학과가 다시 올린 본부 글, 졸업요건·자격 글이 맨 위에 뜬다.

그 밖: 오늘 학식, 북마크와 일정 달력, 휴대폰 캘린더 파일(.ics) 내보내기, 키워드 모아 보기·숨기기.

## 6. 결과 화면

이번 주 한 줄 → 오늘 학식 → 내 학과 카드(학과를 넣었을 때) → 모두에게 필요한 것(학사·장학·생활관) → 내 학과와 가까운 것 → 그 밖. 글을 누르면 상세 창(게시일, 마감과 출처, 첨부 이름, 북마크)이 뜨고, 거기서 원문으로 간다.

## 7. 데이터 출처와 수집 방식

실제로 넣은 것 (11/26, [collector/sources.json](../collector/sources.json)):

| 정보원 | 요청 수 |
|---|---|
| 본부 공지사항 전체 (50건) | 1 |
| 학생생활관, 국제교류, 진로취업 clip | 3 |
| 학과: 약학대학, 간호대학 (시범) | 2 |
| 제대로 산학1번지 (마감일 칸, robots.txt 없음) | 3 |
| 중앙도서관 공지 (JSON) | 1 |
| 학식: 백두관·6호관·사라 | 3 |

한 바퀴 13번 요청, 30초쯤 걸린다. 1호관은 업체 사이트·인스타 링크만 둔다.

- GitHub Actions 가 하루 4번(07·12·17·22시) 게시판 첫 페이지를 읽어 JSON 파일로 만들고, GitHub Pages 가 그 파일을 보여 준다. 서버와 DB 가 없다.
- 한 곳이 실패하면 그곳은 이전 데이터를 그대로 보여 주고, 실패 메일이 온다.
- 제목에 적힌 마감일(예: "(~12/4)")은 뽑아서 "마감 임박"에 쓴다. jedaero 는 접수 종료일 칸을 그대로 쓴다.
- 학과가 본부 글을 다시 올린 것은 제목으로 묶어 한 번만 보여 준다.
- 저장하는 것: 제목, 날짜, 작성 부서, 첨부 이름, 원문 링크. 본문과 작성자 칸은 저장하지 않는다.

### robots.txt 대응

학교 본부 사이트들은 robots.txt 가 전체 차단(`Disallow: /`)이다. 그래서 이렇게 한다([07](07_정보원_종합.md) 5절).

- 목록 첫 페이지만, 하루 2~4회, 요청 사이 2~3초.
- 요청에 서비스 이름과 저장소 주소를 밝힌다.
- 모든 글에 원문 링크. 본문·포스터는 옮기지 않는다.
- 학교에 협조 메일을 보낸다 (보낼지 아직 정하지 않음, [07](07_정보원_종합.md) 8절).

## 10. 한계

- 학교 사이트 구조가 바뀌면 수집이 멈출 수 있다. 화면에 마지막 갱신 시각을 띄운다.
- 서버가 없어 푸시 알림이 안 된다. 화면의 "새 글"·"마감 임박" 표시와 .ics 로 대신한다.
- 마감일이 첨부 이미지 안에만 있는 글은 지금은 마감일을 못 읽는다.
