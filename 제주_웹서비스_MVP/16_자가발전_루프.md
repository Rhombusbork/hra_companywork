## 끊겨도 괜찮게

루프는 언제든 끊길 수 있다(PC 절전, 권한 거부, 세션 종료). 그래도 사이트가 깨지거나 일이 사라지지 않게 한다.

- **작업은 `loop` 브랜치에서.** `main` 은 늘 배포 가능한 상태로 둔다. 바퀴 끝에 시험을 통과한 것만 `main` 에 합쳐 push 한다.
  봇의 데이터 커밋은 `main` 에 쌓이므로 바퀴 시작 때 `main` 을 `loop` 에 합친다.
- **일을 작게 쪼갠다.** 한 바퀴에 끝나지 않을 일은 백로그에 하위 단계(`P0-1a`, `P0-1b` …)로 나눠 적고, 단계마다 커밋한다.
- **하던 일 표시.** 시작할 때 아래 "지금 하던 일" 에 한 줄 쓰고 `loop` 에 커밋한다. 끝나면 비운다.
- **다음 바퀴가 처음 할 일**: `git status` 와 "지금 하던 일" 을 본다.
  - 커밋 안 된 변경이 있으면 → `loop` 에 "WIP: …" 로 커밋해 살려 두고, 그 일을 이어서 한다.
  - 시험이 깨진 채 남아 있으면 → 고치거나, 못 고치면 마지막 통과 커밋으로 되돌리고 17 에 적는다.
- 끊긴 뒤 사용자가 같은 `/loop` 문장을 다시 넣으면 여기서부터 이어진다.

## 한 바퀴

1. `git checkout loop`(없으면 `main` 에서 만든다) → `git pull --rebase origin main` 대신 `git fetch && git merge origin/main`. 위 "끊겨도 괜찮게" 의 처음 할 일. 이 파일과 17 의 마지막 몇 줄을 읽는다.
2. 아래 백로그에서 `[ ]` 인 맨 위 일 하나(작으면 둘)를 한다. "지금 하던 일" 에 적고 시작. 조사 주제는 웹검색을 넉넉히(여러 검색을 한 번에).
3. 사이트를 고쳤으면 `python tests/ui_check.py` → 통과하면 `loop` 에 커밋 → `main` 에 합쳐 push (`git checkout main && git pull --rebase && git merge --no-edit loop && git push && git checkout loop`).
   통과 못 하면 `loop` 에만 커밋하고 `main` 은 건드리지 않는다.
4. 백로그에 `[x]`, 하다가 나온 새 일은 알맞은 자리에 `[ ]` 로 추가. 17 에 한두 줄. "지금 하던 일" 비우기.
5. 다음 바퀴 예약. 할 일이 남았으면 짧게(60~120초), 다 끝났으면 백로그 R 주제를 더 판다.
